Can a better model make an agent worse? In one of our experiments, a later model completed a task in 14 turns on its own. Paired with an older harness, the same model hit the 50-turn limit without finishing. The model had changed, but the code guiding it hadn't kept up.

That mismatch is what motivated **JoMoHa**, our approach to training a language agent and its harness together with reinforcement learning.

[Read the paper](https://arxiv.org/abs/2611.11499) · [Explore the code](https://github.com/xudongwu-0/coevolve)

## One task, two learners

A harness is the code around a model that shapes how it works through a task: what it sees, what it keeps track of, and how it interacts with the environment. We made that code something the system could learn to write.

The **Engineer** generates an executable harness. The **Solver** uses it to act in the environment. The outcome of that run trains both: the Solver learns to execute the task, and the Engineer learns to write a harness that helps this Solver succeed. The key is that both learn from the **same run**. Rather than relying on a fixed model to suggest harness improvements, we train the model that writes them.

## What changed when we trained them together?

JoMoHa achieved **70.3% average task success** across ALFWorld, WebShop, and DBBench, **7.2 percentage points above WHALE**. It led the methods we compared on all three: **97.0%** on simulated household tasks (ALFWorld), **45.8%** on goal-directed shopping (WebShop), and **68.0%** on database interactions (DBBench).

On ALFWorld, keeping the Engineer frozen while it continued to generate fresh harnesses reached **90.5%**. Training the Engineer alongside the Solver brought that to **97.0%**.

For us, the exciting part is that the agent learns not just **how to do the task**, but also **how to improve the way it does the task**. Both skills improve from the agent's own experience.
